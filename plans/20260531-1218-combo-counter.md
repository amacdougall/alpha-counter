# Combo Hit Counter

## Context

The visual redesign (see commit history around 2026-05-31) reserves a slot
beneath the VS combo disc for a "N HITS" readout that shows how many
discrete damage / heal inputs make up the current combo. The CSS class is
already defined (`.combo__hits`) and shipping in `resources/public/css/app.css`.

The first redesign pass left the counter unwired so the visual change could
land without touching the channel pipeline. This plan picks the work back
up. The end goal is a tiny addition — `[:div.combo__hits "3 HITS"]` rendered
below the existing combo disc whenever a combo is in progress.

The only reason this is non-trivial is that the existing combo plumbing in
`channels.cljs` only tracks damage *amount*, not hit *count*. So the work
is: add a `hit-count` channel transformer that mirrors the existing
`running-total` but emits hit counts instead of damage totals, tap it off
the same `mult` that already feeds `running-total` and `delayed-total`, and
wire its output into app-state.

## Files to change

### 1. `src/alpha_counter/channels.cljs`
Add `hit-count` alongside the existing transformers. It's structurally
identical to `running-total` but emits an integer hit count instead of a
running damage sum, and emits `:reset` after `ms` of inactivity. Place it
between `running-total` and `delayed-total` to keep related helpers
together.

```clojure
;; Returns a channel which counts hits received from the input channel.
;; Emits 1, 2, 3, … as inputs arrive. After ms of inactivity, emits :reset
;; and resets the counter. The numeric *value* of each input is ignored —
;; only its arrival counts as a hit (so both damage and healing combos
;; advance the counter).
(defn hit-count [in ms]
  (let [out (chan)]
    (go-loop [n 0]
      (if (zero? n)
        (let [_ (<! in)]
          (>! out 1)
          (recur 1))
        (let [[_ ch] (alts! [in (timeout ms)])]
          (if (= ch in)
            (let [n+1 (inc n)]
              (>! out n+1)
              (recur n+1))
            (do
              (>! out :reset)
              (recur 0))))))
    out))
```

### 2. `src/alpha_counter/data.cljs`

**App state.** Add a sibling to `:running-total`:

```clojure
(defonce app-state
  (atom
    {:characters-selected false
     :players [{:id :player-one} {:id :player-two}]
     :current-player-id :player-one
     :running-total 0
     :hits 0                  ; <— new
     :history []}))
```

**Channel wiring.** In `player->channels`, tap another consumer off the
existing `mult` and route it through `hit-count`. A new `go-loop` mirrors
the existing running-total updater — push numeric values into
`(:hits @app-state)`, push 0 on `:reset`. Both players write into the same
slot; whichever is currently active determines what's shown, which is fine
because only one combo is in flight at a time.

```clojure
(defn- player->channels [player]
  (let [hits-in (chan)
        mult (mult hits-in)
        running-total (-> (tap mult (chan))
                          (channels/trickle damage-change-speed)
                          (channels/running-total combo-timeout))
        hit-count (-> (tap mult (chan))
                      (channels/hit-count combo-timeout))     ; <— new tap
        damage (-> (tap mult (chan))
                   (channels/delayed-total combo-timeout)
                   (channels/trickle health-change-speed))]
    (go-loop []
      (when-let [n (<! running-total)]
        (om/update! (app-cursor) [:running-total] n)
        (recur)))
    (go-loop []                                                ; <— new loop
      (when-let [v (<! hit-count)]
        (om/update! (app-cursor) [:hits]
                    (if (= v :reset) 0 v))
        (recur)))
    (go-loop []
      (when-let [v (<! damage)]
        (apply-damage player v)
        (recur)))
    {:hits hits-in
     :running-total running-total
     :hit-count hit-count
     :damage damage}))
```

Rename the local `hits` binding to `hits-in` (current naming clashes with
the new `:hits` app-state key and the `hit-count` channel). Update
`return-to-character-select!` to also reset `:hits 0` for cleanliness.

### 3. `src/alpha_counter/views/life_counter.cljs`
The `combo` helper currently renders only `.combo__text`. Add the
`.combo__hits` element underneath, conditional on a non-idle combo with at
least one hit.

```clojure
(defn- combo [{:keys [running-total hits]} _owner]
  (reify
    om/IDisplayName
    (display-name [_] "ComboView")
    om/IRender
    (render [_]
      (let [idle (#{0 :reset} running-total)
            healing (and (not idle) (neg? running-total))
            magnitude (Math/abs running-total)
            text (cond
                   idle "VS"
                   healing (str "+" magnitude)
                   :else (str "−" magnitude))
            active-state (cond healing "healing"
                               (not idle) "damage")
            show-hits? (and (not idle) (pos? hits))]
        (html [:div {:class (classes "combo" active-state)}
               [:div {:class "combo__text"} text]
               (when show-hits?
                 [:div {:class "combo__hits"}
                  (str hits " HIT" (when (not= hits 1) "S"))])])))))
```

Call site moves from `(om/build combo (:running-total app))` to
`(om/build combo {:running-total (:running-total app) :hits (:hits app)})`.

## Edge cases worth thinking about

- **Undo.** `undo!` pushes a counter-hit (`(- n)`) into the same `hits-in`
  channel. With the naive implementation, that counts as another hit and
  the counter ticks up. That's a known quirk; the alternative (subtracting
  on undo) requires a separate channel and breaks the "one mult, multiple
  taps" symmetry. Accept it; document with a comment in `undo!`. A later
  pass could split undo into its own channel if the UX bites.
- **Heal/damage mix in one combo.** `running-total` can swing through zero
  mid-combo (heal 6 → damage 8 lands on +2). `hit-count` ignores the sign
  and just counts arrivals, so the readout stays sensible.
- **Rematch / return to character select.** Channels are already torn down
  and rebuilt in `ready!` (`(reset! channels (build-channels app))`), so
  the new go-loops die with their channels — no leak. Just ensure
  `return-to-character-select!` zeroes `:hits` alongside `:running-total`.
- **App-state slot is shared.** Both player channels write to
  `(:hits @app-state)`. Only one combo runs at a time in practice (the
  opposing player's channel is idle), so there's no race. Same assumption
  the existing `:running-total` already makes.

## Verification

1. Pick two characters, start a fight.
2. Tap 5, 6, 4 quickly (within `combo-timeout`/3 s). Expect:
   - The combo disc shows `−15` mid-combo.
   - `3 HITS` appears below the disc.
3. Wait 3 s. Disc returns to "VS"; hit counter disappears.
4. Tap a `+12` heal. Expect: mint-green disc with `+12`, `1 HIT` below.
   Tap another `+6`. Expect: `+18`, `2 HITS`. Wait, then disc returns to
   idle and counter clears.
5. Switch current player and exchange hits. Counter resets between sides
   (because `combo-timeout` elapses between switches in the natural
   playing pattern). If it doesn't reset because the same player took
   another hit inside the timeout window, that's correct behavior.
6. Use Undo during a combo. Confirm the counter ticks up (known limitation
   noted above) but doesn't break the disc or app-state.
7. Hit Rematch / Character Select — counter is zero on return to play.
